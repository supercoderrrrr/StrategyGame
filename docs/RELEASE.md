## 构建

在完整私有工程中使用 Unity `2022.3.62f2`，选择 Windows x86_64。检查 Build Settings 场景顺序为：

1. `Assets/Scenes/MainMenuScene.unity`
2. `Assets/Scenes/Level1.unity`

构建到忽略的 `Builds/Windows`。Unity Build 需连同数据目录与运行库一起压缩，不能只分发 EXE。保留 Unity 实际生成的所有必需运行文件，并附操作说明；不需要在试玩包中包含调试符号或备份调试目录。

## 发布前试玩检查

- 主菜单、关卡选择、暂停、重开与退出。
- 单位选择、行动点、移动、攻击/技能及敌方回合完整结束。
- 水面成本、开关门、箱体破坏后的路径可用性。
- 玩家进入房间并停止后再播放迷雾消散。
- 厚墙、重叠墙、墙门及切换单位的遮挡表现。
- 拆弹成功、单位死亡、倒计时结束等胜负流程。
- 首次启动与再次启动；在没有安装 Unity 的 Windows 环境运行。
- 检查构建日志/运行日志，没有未处理异常和明显 Shader 错误。
- 从购买/下载记录确认第三方资源允许用于该游戏 Build。

## GitHub Releases

首次经验证的试玩版建议使用 `v0.1.0`，压缩包名为 `StrategyGame-Windows-v0.1.0.zip`，上传到公开作品集仓库的 Releases，避免提交大型二进制到 Git 历史。

发布说明应记录 Unity 版本、操作、任务目标、已知问题、验证范围与对应私有工程提交。公开源码和私有工程初始提交可以分别存在，不必伪造相同的提交哈希。

发布后再将实际 Release URL 与已录制的演示视频链接添加到公开 README 顶部。
